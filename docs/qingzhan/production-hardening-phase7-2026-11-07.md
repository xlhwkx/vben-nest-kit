# 第七轮修复：上传预算、审计积压、S3 配置与数据维护

本轮落实第六轮复核中的四项主要问题。修改均在本地工作区，未提交、推送或部署线上。仅在本机隔离数据库上执行测试删除，没有删除用户业务数据。

## 已落实的变化

| 项目 | 结果与取舍 |
| --- | --- |
| multipart 字段累积 | 上传只接受一个名为 file 的文件，fields=0、parts=1，同时约束字段名/字段大小。第六轮 6 MiB 普通字段请求从可成功上传改为 400，存储不执行。文件大小上限本身保持独立，恰好达到上限允许，超过返回 413 |
| 上传并发预算 | 新增 UPLOAD_MAX_CONCURRENT，默认每进程 4，解析前占用名额，覆盖解析、校验和存储，超出返回 503，无等待队列。实际 HTTP 回归验证名额耗尽、恢复与客户端部分上传中断后释放 |
| 审计积压 | 尽力审计默认最多 256 条（活动+排队），同时最多 4 个写入；满额丢弃新尽力审计并计数，避免故障下无限增加数据库任务与内存。事务内成功审计绕过该队列，队列满时仍执行且失败仍回滚业务 |
| 审计身份隔离 | 入队时快照请求身份、请求 ID 和脱敏明细，避免排队后在另一个请求的 AsyncLocalStorage 上下文中写入，或明细对象后续修改影响审计 |
| 数据库预算 | PrismaPg 默认池大小 10，连接/池等待 3 秒，PostgreSQL 服务端单语句 15 秒，可配置且启动校验。真实 PG 回归运行能返回整数的慢 SQL，确认因 statement timeout 取消，而非仅对 Promise 做超时；之后连接仍可查询 |
| S3 部署配置 | Compose 补齐 S3 endpoint、region、bucket、凭据、path-style、公网前缀、上传和资源预算。S3 模式缺凭据拒绝启动；local 不要求 S3 凭据。渲染结果在生产镜像内通过当前配置校验器验证 |
| S3 请求/生命周期 | 整次 PUT 默认 15 秒 AbortSignal 预算，含 SDK 重试；超时返回 503。存储 provider 由 Nest 调用生命周期，移除工厂中的重复初始化；关闭时销毁 SDK 客户端 |
| 数据维护入口 | 增加 dist/cli/maintain-data.js / pnpm maintenance:data，默认仅预览。必须给出 sessions 或 audit、过去的 UTC 截止时间；--apply 才删除，batch-size/max-batches 共同限制每轮工作量 |

## 审计队列的可靠性边界

后台队列保护的是尽力审计路径，不是可靠消息队列。满额丢弃和数据库写入失败均通过指标观测，停机 drain 处理已经接收的队列并拒绝新增。数据尚在内存，进程崩溃或 drain 超时仍可能丢失；没有新增 outbox。

指标包括 active、pending、failed_total 和 dropped_total{reason=capacity|shutdown}，名称以 qingzhan_audit_background_ 开头。生产模板默认关闭 metrics，运维需开启指标、配置 token、抓取与告警；单有计数代码不等于告警已经配置。容量与并发应结合数据库连接预算设置，增加队列长度不能消除持续故障。

已经事务化的管理和有效认证会话成功审计不受队列丢弃策略影响。本轮单元回归明确在队列满时验证事务内审计仍被调用，并保留此前审计失败回滚的真实数据库回归。

## 维护命令与会话语义

完整参数及容器内命令见 deploy.md。每批使用带参数 SQL、固定目标表和 FOR UPDATE SKIP LOCKED，锁等待 1 秒、单语句 5 秒、事务 10 秒；最多 5000 行/批、100 批/次，默认 500 行、20 批。输出初始候选数、实际删除数、批次和上限。候选计数只是当时快照，另有写入或锁定时需再次执行。

sessions 按 expiresAt 严格早于截止时间删除，不按 revokedAt 删除。未过期的旧令牌即使已经旋转撤销，仍可能用来注销其整个会话家族，因此保留这些记录。回归覆盖预览不改数据、批次上限、截止时间边界、重复执行、并行执行，以及未过期 revoked 祖先和活动后代的保留。

audit 必须显式选择，只按 createdAt 与给定截止时间删除。本轮不默认设置审计保留期、不安装自动任务，也不把删除称为归档。生产使用前仍需要确定业务/合规保留期、归档位置和恢复流程。中途失败时先前批次可能已提交，可安全重复运行。

## 仍有范围限制

上传预算按进程计，不能替代入口总请求体/接收超时、集群配额和磁盘容量治理；部署文档给出了代理设置示例。S3 取消或响应丢失时远端可能已经保存对象，尚无孤儿对象清理或跨存储 outbox。本地文件系统卡死也不由 S3 超时机制处理。

本轮未完成真实云 S3/MinIO 的权限、公开 URL、网络和兼容验收；MinIO 测试镜像拉取未成功，未以协议夹具冒充该项验收。SMTP 和审计归档 worker 继续是已标注的可选骨架。租户隔离、业务数据范围、私有文件 ACL 和长时间/多实例容量验证仍按已有报告的边界处理。
