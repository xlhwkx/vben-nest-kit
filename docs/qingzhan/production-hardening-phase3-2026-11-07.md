# 第三批加固：输入边界、分页与错误语义

> 后续部门并发、字典版本迁移及最新镜像验证见[第四轮深挖记录](./production-hardening-phase4-2026-11-07.md)。本文保留第三批完成时的基线。

继续在[第二批加固](./production-hardening-phase2-2026-11-07.md)基础上处理接口一致性。本批不修改数据库结构，不新增依赖；修改留在本地工作区，没有提交、推送或部署线上服务。

## 解决的问题

| 原有行为 | 本批行为 |
| --- | --- |
| 列表参数靠 TypeScript 的 string 标注，重复参数数组可能在 `.trim()` 处抛异常 | 用户、角色、字典类型、字典数据、审计列表在服务查询前使用统一运行时校验；重复或嵌套的已知标量参数返回 400；方括号嵌套查询语法也拒绝 |
| `parseInt` 接受 `1abc`、小数前缀；极大页码可能导致异常或昂贵偏移 | page/pageSize 只接受正整数字段，默认 1/20，每页最多 100；偏移 `(page - 1) * pageSize` 最多 1,000,000，超出返回 400 |
| 非法 UUID 可进入 PostgreSQL 后返回 500 | 管理写接口的路径 ID、用户/角色过滤 ID、部门 ID、角色/菜单绑定数组和父节点 ID 在进入查询/修改前校验 |
| 无效状态、性别或日期过滤被忽略，用户误以为筛选已生效 | 非空非法枚举、无效日历日期、无时区的时间戳及反向日期范围返回 400 |
| 审计日期过滤按运行环境时区处理，与用户/角色列表不一致 | 三类列表统一调用同一时间范围解析器；日期按上海日历日计算，结束日期包含当天最后一毫秒 |
| 排序数值未限制为数据库整数范围 | 字典 sort 和菜单 meta.order 限制为 PostgreSQL int32；小数和溢出返回 400 |
| 部分必填名称校验后才 trim，纯空白可穿过入口；字典空更新成功 | 必填名称/编码先 trim 再检查；用户、角色和字典更新拒绝空对象及只有未知字段的对象 |
| 字典数据更新提交不同 dictCode 被静默忽略 | 同一个 dictCode 可随表单重传；尝试移动到另一字典返回 400，应在目标字典新建数据 |
| 数据库约束竞争通常返回通用 500 | 已知 Prisma 约束、记录缺失和竞争错误映射到稳定的 400/404/409/503；未知错误仍返回通用 500，保留内部日志 |

菜单名称/路径和字典编码存在性检查，以及普通字典拉取接口也校验完整查询对象。登录用户名、密码与验证码字段增加长度上限，密码内容不做 trim。公共校验错误最多输出 8 条，不回显提交值。角色/菜单绑定数组最多 1,000 项，UUID 转为小写后去重。

角色、字典数据、审计分页增加唯一 ID 排序兜底，避免同一时间或同一排序值下顺序不确定；这不提供跨多个请求的一致性快照，实时写入时分页仍可能变化。

## 兼容性与二开约定

- 双 API 前缀 `/api` 与 `/api/v1`、响应信封、刷新令牌纯字符串响应保持现有合同。
- 管理分页的空字符串或省略值使用默认值；不再把 0、负数、`1abc` 或小数纠正为有效分页。pageSize 超过 100 从截断改为返回 400。深分页超过偏移上限，应增加过滤或另行设计游标/导出接口。
- 文本过滤的空白值表示未筛选；枚举过滤仅支持明确的合法值。未知的普通平面 Query 字段仍忽略，已知字段的数组/对象值拒绝；方括号嵌套 Query 语法拒绝。
- 日期支持真实 `YYYY-MM-DD`，或包含 `Z`/`±HH:MM` 时区的 ISO 时间戳；例如上海 2024-01-31 范围为 `2024-01-30T16:00:00.000Z` 至 `2024-01-31T15:59:59.999Z`。模糊日期字符串不再接受。
- 树根保留 `0`、`"0"`、null、空字符串及既有字符串标记 `"null"`/`"undefined"`，统一为数据库 null；其他非 UUID 父节点拒绝。省略父节点时仍遵循各接口原有更新语义。
- 用户和角色的绑定字段省略时保留绑定，显式 `[]` 时清空。字典允许部分字段更新；菜单、部门仍按原合同提交完整必填字段。普通未知 Body 字段仍被剥离，非空更新必须包含至少一个已知字段。
- HTTP Guard 仍先执行。没有权限的请求不会因为参数错误而获得更具体的管理数据反馈。

数据库错误的通用映射：P2000 → 400，P2002/P2003/P2034 → 409，P2025 → 404，P2024 → 503。业务服务已经提供的具体 HttpException 优先保留；不会用数据库原始 message、索引名或目标字段作为客户端错误内容。503 和并发冲突应采用有限重试；实际外部副作用仍需要业务自身的幂等策略。

## 验证

- 单元与回归：19 套件、82 项通过，包括日历与偏移时间语义、数据库错误映射和敏感信息不泄漏。
- 真实 PostgreSQL 16 / Redis 7：3 套件、96 项 E2E 通过。新增 46 项输入边界场景覆盖分页、查询数组/对象、UUID、枚举、日期、排序、空更新、根节点、字典更新和登录长度；保留此前 50 项认证、授权和 CRUD 回归。
- Nest 构建、运行/测试/seed 类型检查、涉及 TypeScript 文件的只读 ESLint 和 `git diff --check` 通过。
- 使用新建的临时数据库和 Redis，未修改项目 `.env`；测试完成后清理本批容器。详细测试日志保存在仓库外。

本批未重新构建生产镜像；第二批的镜像启动/停机证据对应第二批代码。发布本批代码时应重新构建镜像并执行 CI 冒烟。

## 剩余边界

本批覆盖持久化管理接口、审计查询、普通字典拉取及登录输入，未统一所有演示接口的宽松行为。运行时校验以 HTTP 入口及列表服务为主；二开代码绕过这些入口直接调用写服务时，必须复用 schema 并维护业务校验。

分页偏移上限只是资源边界，不代表已有容量保证。组织/租户数据范围、部门树并发修改保护、剩余审计的可靠投递、依赖公告处理和备份恢复/压力测试仍是后续工作。
