# 基础字典初始化与系统管理数据契约修复

基础字典原来只存在于开发 seed，生产空库 bootstrap 不会创建，用户管理却依赖 `user_gender`。现将三套字典抽成独立系统数据定义，由新库 bootstrap 和开发 seed 共用；已有库通过 `provision:dicts` 显式补齐。只创建缺失类型，保留已有类型、条目和停用状态；所有写入及升级审计处于同一事务，升级命令沿用系统管理写锁和管理员权限复核。

菜单链路核对结果：数据库 `parentId` 映射为管理接口 `pid`，列表通过 `children` 返回树；`/menu/all` 只返回角色授权且启用、未删除、祖先完整的路由，排除按钮；按钮的 `authCode` 参与接口权限；更新仍携带 `version` 防止旧编辑覆盖新数据。目录、页面、内嵌、外链、按钮五种类型与前端保持一致。

修复菜单编辑中的具体契约缺口：

- 显式声明管理接口的 `status` 类型。
- 激活菜单字段使用 `meta.activePath`；不再用原始相对路径查重接口验证最终绝对路径，避免默认字典详情页被误拒绝。
- 外链也填写内部路由地址；按钮提交明确的空路径。
- 内嵌菜单指定 `IFrameView`；切换类型清理过期页面组件及 URL 元数据。
- 管理列表与动态路由均返回数据库中的排序值 `meta.order`，编辑页增加整数排序输入，避免初始化菜单缺少 JSON order 时被重置。

无需新增数据库迁移，不自动连接或修改已有部署。已有库先备份、部署并构建新版本，再按生产验收指南执行补齐命令。

继续核对用户、部门、角色和字典管理后，补充修复：

- 用户列表按实际 `{ items, total }` 分页结构声明；用户、角色、部门及字典响应移除任意字段索引，写入类型与只读响应分开。
- 用户部门与数据库一致，允许为空；完整编辑清空部门、上级部门或字典颜色时分别提交 `deptId: null`、`pid: null`、`color: null`。局部 API 更新仍保留“省略即不修改”的语义。
- 用户编辑根据 `System:User:AssignRole` 显示角色选择并决定是否提交角色；拥有授权时清空选择发送 `roles: []`，避免普通资料修改误触角色授权检查。删除按钮使用正式的 `System:User:Delete` 权限码。
- 部门搜索保留原始树，递归匹配子部门并保留祖先；选择事件通过组件模型取得部门 ID，支持取消选择，避免把整个节点对象作为查询参数。
- 字典数据编辑显式选择文本或数字，数字回填为输入文本后按原类型编码，保留文本 `"001"`；数字拒绝空白、非数字和无限值，排序限制为非负 int32 整数。清除颜色与提交数值 `0` 均有回归覆盖。
- 权限树同步半选节点时使用原始行的 ID，避免把半选祖先误当成全选节点；浏览器回归覆盖点击半选父节点选中全部子节点，以及真实部门筛选/取消筛选请求。

同时移除 PR 标题检查的 WIP commit-status 写入，保留标题校验和只读令牌权限。旧配置的 `wip: true` 会调用未授权的状态写入接口而失败；该 `pull_request_target` 工作流读取主分支定义，因此修正需合并后生效。

验证采用本机静态类型/lint/结构检查，以及远程隔离 CI 的表单编解码回归、真实 PG/Redis E2E 和生产镜像初始化/重复补齐/保留定制烟测。本机不运行服务、容器、浏览器、单元/E2E 或生产应用构建；运行验证以对应提交的 CI 结果为准。
