# 第十轮：菜单一致性与管理编辑冲突

本轮落实整体复核 A05—A07，范围为菜单可选字段语义、角色路由祖先约束、用户/角色/菜单的更新版本，以及 playground 对应提交链路。修改在本地工作区，未提交、推送或部署线上。

## 修改后的行为

菜单更新仍要求 name/path/type，省略 pid/status/authCode/component/redirect/meta 时保留原值。pid 显式 null 移到根；可空文本传 null 或空字符串清空。meta 省略保留，传对象整体替换，null/空对象清空；传入新对象不含 order 时同步将排序归零。playground 清空父级选择器时显式发送 null。

角色写入包含页面节点时必须显式选择全部未删除祖先，缺少祖先返回 400。服务端不自动增加 RoleMenu 或 API 权限；按钮仍可独立授权。权限树提交半选祖先。菜单移动/类型改变会校验受影响角色的路由约束，失败时连同版本和审计一起回滚；按钮不能作为菜单父级或包含子节点。

用户、角色、菜单增加独立的正整数 version。列表、创建、更新均回传，PUT 必须提交读取时版本；缺失/非法版本返回 400，旧版本返回 409。更新先在事务内以 id + version 原子认领记录，再修改字段、关联和审计，竞争中的同版本表单只能有一个成功。原有锁内鉴权、授权范围及最后管理员保护继续执行。

新增迁移 `20261107030000_management_edit_versions`。已有三类记录默认 version=1；PostgreSQL 行更新触发器推进版本，RoleMenu / UserRole 的增删改也通过触发器推进聚合版本，覆盖只改关联、直接关系写入、关联所有者改变和 FK 级联。版本随事务回滚，不占用认证 tokenVersion；一次保存可能推进多次，客户端使用服务端返回值，不能自行加一。

角色/用户列表使用 Repeatable Read 事务，使记录版本、关联 ID 和分页计数来自同一数据库快照，避免 Prisma 分次读取关联时拼出不同版本的数据。菜单列表本身是单条读取。

playground 表单独立保留打开时的版本，状态切换携带行版本并采用响应的新版本；版本不会依赖表单库是否保留未注册字段。冲突响应包含可直接展示的刷新提示，失败后保持抽屉和输入，未增加自动重发旧表单的逻辑。

## 验证

新增 `management-edits.e2e-spec.ts` 的 17 项真实 PostgreSQL/Redis 回归，覆盖：

- 菜单省略保留、显式清空、meta 整体替换及排序同步。
- 祖先缺失拒绝、完整授权生成动态路由、按钮独立授权且不增加祖先权限。
- 菜单移动失败的版本/父级回滚，以及显式补授权后的成功移动。
- 用户/角色旧表单无法恢复撤销的关联，菜单旧表单无法重新启用已禁用记录。
- 三类资源同版本并发保存只成功一次；版本缺失、类型错误、越界及空更新拒绝。
- 事务审计失败回滚版本，直接关联增删改推进新旧所有者版本，事务中止恢复版本。

## 升级与剩余范围

这是一项接口变更：先在测试环境验证迁移，部署时让后端与携带 version 的客户端配套更新；旧客户端的无版本 PUT 会被拒绝。迁移不自动补齐历史缺祖先授权，避免改变已有权限范围；相关角色需要管理员明确复核并保存。历史角色在修改授权或受影响拓扑时会接受新规则校验。

本轮版本前置条件覆盖用户/角色/菜单 PUT；部门、字典和 DELETE 尚未增加同类前置条件。版本只处理编辑冲突，不能替代管理鉴权或业务数据隔离。禁用祖先仍会隐藏路由，接口权限与导航权限继续各自按原有语义计算。
