# 第十二轮：菜单内容与认证上下文边界

本轮修复源码复核 S11-01—S11-04。修改在本地工作区，没有提交、推送、部署或数据库迁移。遵循用户选择的源码工作方式，没有启动服务、容器或浏览器，没有执行单元/E2E/浏览器测试。

## 修改后的行为

### 菜单 iframe 与链接

- 后端为菜单 meta 中已知的标题、图标、权限、徽标、布尔开关和数量等字段增加类型检查；扩展字段保留，不能通过 iframeSrc/link 绕过 URL 检查。
- iframeSrc/link 只接受不含控制字符、空白或用户凭据的绝对 HTTP(S) URL。服务层在事务内校验最终有效 meta；embedded 必须有 iframeSrc、link 必须有 link，其他类型不得带对应字段。省略 meta 仍保留原值，显式对象仍整体替换；历史不合法配置需管理员纠正后保存。
- /menu/all 输出过滤历史危险 URL；前端动态路由转换、iframe 实际渲染也独立过滤。已缓存标签页中的危险 iframe URL 不会进入 iframe src。数据库原数据保留，便于管理员排查和修正，未自动修改或删除历史记录。
- iframe 使用 `sandbox="allow-forms allow-scripts"`，不授予 allow-same-origin 或父窗口导航能力，referrerpolicy=no-referrer。合法 URL 不等于可信内容，不建立任意 HTTP(S) 页面与管理后台的同源信任。
- playground 切换为普通菜单时去掉旧 iframeSrc/link，避免表单隐藏字段残留。

兼容影响：相对 URL、带凭据或未编码空格的 URL 被拒绝；依赖同源存储、嵌入登录、弹窗、下载或顶层导航的 iframe 可能需要业务适配。需要扩大能力时，应评估独立来源和来源白名单，不能直接同时放开脚本与同源隔离。

### 账号一致性与请求重放

- 配套前端给每个请求附带本地登录世代、共享随机变更标记及原用户标识；发送、成功响应、401 处理、刷新前后及请求重放均检查相应上下文。
- 显式登录/退出推进世代，拒绝之前正在等待的请求、响应和延迟刷新结果。相同前端 origin 的其他标签页在下次请求或刷新检查时发现随机标记变化；不广播凭证。被动重新认证只重置本地上下文，不更新其他标签页标记，也不撤销服务端 Cookie。
- 登录、刷新和退出复用按 API origin 的协调锁。账号变化后的登录清除旧用户、权限、标签页状态及动态路由，再加载当前账号信息。旧请求的失败回调不能清除已经建立的新本地登录。
- refresh/logout 额外支持可选 expectedUserId；配套前端从原 access JWT 的 sub 提取。与刷新 Cookie 的用户不匹配时，服务器在令牌消费或撤销前拒绝，不清共享 Cookie。
- 保留 refresh 成功返回纯 access token 字符串、旧客户端可不传请求体的兼容约定。更新配套前端才能获得完整请求上下文保护；其他客户端应采用相同绑定策略。

边界：JWT 解码仅用于客户端比较，服务端仍负责签名与权限验证；没有可识别 sub 的自定义 opaque token 不能走这两个前端的新自动续期。不同前端 origin 不共享 Web Locks/localStorage；禁用存储或不支持 Web Locks 的环境，跨标签页协调能力会降级，但原用户与刷新结果的比较及服务端 expectedUserId 核对仍在。这里不宣称支持同一 Cookie 范围内多个账号各自独立续期，账号切换后旧页面应重新认证。

### 退出失败

- 服务器撤销失败或网络错误时，前端不再清空 store 并伪装成成功退出；保留当前状态、显示持续错误提示，允许再次点击退出。
- 成功后才清理 store、动态路由并返回登录页；世代检查阻止延迟刷新恢复退出前的前端凭证。
- logout 的预期用户核对也避免旧账号页面撤销共享 Cookie 中其他账号的会话。无法确认服务端退出时仍显示未完成，不能保证网络断开时撤销立即生效。

### Readiness

- ready 去掉跳过限流的策略，独立限制每 IP 每分钟 30 次；live、旧基础探针和 metrics 保留原有跳过策略。
- 同实例同一时刻只执行一组依赖探测；成功和失败均缓存 1 秒，依赖探测结束后才释放并发位置。保留已有数据库、Redis 超时。
- 响应 Cache-Control=no-store，避免中间代理继续缓存状态。内部缓存最多导致 1 秒状态延迟，健康指标计数反映实际探测而非每个缓存命中的 HTTP 请求。
- 仍建议 ingress 只向内部开放依赖探针；本轮不是网络访问控制或集群全局并发控制。

utils 独立检查的错误位于 `generate-menus.ts`、`generate-routes-frontend.ts` 及对应 `__tests__` 文件：包括 RouteRecordRaw 测试数据断言、可能为 undefined 的数组元素、RouteMeta 字段被推断为 unknown。已用 Git 确认这 4 个文件与 HEAD 一致。本轮未改动这些文件，也未扩大为修复整个 utils 单包检查；实际两个前端的类型检查通过，不能据此把独立单包检查也报告为通过。

新增回归用例仅作为后续可执行的验收资产，本轮不报告运行通过数：

- 服务端菜单协议/类型组合、历史 URL 输出过滤。
- 刷新和退出用户不匹配时不旋转、不撤销、不清 Cookie。
- 探针并发合并、成功/失败缓存及过期重探测。
- 前端用户变化、同用户登录世代变化、存储不可用、本地退出后的延迟凭证。
- 401 旧请求不刷新/重放、刷新期间切换身份后拒绝原写入、登录失败不自动刷新。
- iframe URL helper 对危险协议、控制字符、相对 URL 和正常 URL 的处理。

仍需具备运行条件的环境完成上述用例及真实浏览器验收，特别是双账号双标签页、排队写请求、退出失败重试、iframe 正常业务兼容和探针依赖故障。此前轮次的测试结果不作为本轮通过依据。A08—A11 的 CI、完整 OpenAPI、前端交付入口和根快速开始不在本轮修复范围内。
